## What Buzz has that Arc lacks entirely (ranked by relevance to "quick-deploy agentic workhorse, humans+agents side by side, enterprise/federal")

1. **Native multi-user chat/collaboration surface** (channels, threads, forum, DMs, huddles/voice) — Arc has zero native equivalent; this is the single biggest product gap if the goal includes humans and agents literally sharing rooms. (`VISION.md:13-25`)
2. **Git hosting + branch-as-room + code review integration** (NIP-34 patches, CI-in-channel, merge decisions co-located with evidence) — Arc has no git-hosting product surface at all.
3. **Workspace-wide full-text search across everything** (messages, patches, workflow runs, approvals) via `buzz-search` — Arc's search is memory-scoped only.
4. **Mobile client** (Flutter, in progress) and a desktop app (Tauri) — Arc has no mobile or desktop surface.
5. **Protocol-native tool/agent composability** (ACP + MCP with zero coupling, any client × any server) — Arc's tool registry is more of an internal contract than an open protocol boundary; its own MCP client is unwired.
6. **k8s/Helm-based, TLA+-proven multi-tenant deployment story at named scale** (10K humans/50K agents) — Arc's deployment story stops at a single Docker image.
7. **Real-time voice (huddles)** — Arc has a `voice` module (STT/TTS providers) but no room/huddle product concept riding on it.

## What Arc has that Buzz lacks entirely (ranked the same way)

1. **Deep, analogical-retrieval agent memory** (`arcmemory`: 4 stores, embeddings, consolidation, dedup, distiller) vs. Buzz's flat encrypted key-value engram store with manual, unranked retrieval and zero semantic search. This is the gap the team-lead specifically flagged — verified real on both sides, and Arc wins decisively.
2. **16 first-class LLM providers**, including native local-model paths (Ollama, vLLM) — vs. Buzz's 4 providers where "local" only exists as an OpenAI-compat base-URL override.
3. **A working approval-gate mechanism for automation** — Arc's operator-approval subsystem (SPEC-035) is deployed and functioning; Buzz's equivalent workflow feature is a documented, known-broken stub (WF-08).
4. **Browser/web tool-use for agents** (CDP + Browserbase backends) — Buzz's dev-mcp has no web/browser tool at all.
5. **Federal-grade identity/audit architecture as a first-class design constraint** (DID-per-entity, 4 Pillars enforced per tool call, FIPS/FedRAMP tiering) — Buzz's security model is real but not built around federal compliance frameworks.
6. **Self-modifying tool/skill creation** (`create_tool`, `create_skill`, skill marketplace hub connector) — Buzz has no equivalent; personas are pre-authored bundles, not agent-authored capabilities.
7. **Task DAG with dependency gating, reliability watcher, and dead-letter handling** for multi-agent work — Buzz's workflow engine is trigger→steps with no dependency graph or retry/backoff semantics found in `buzz-workflow`.

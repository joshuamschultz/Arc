## Product Overview

### Vision
Arc can state a defensible, reproducible LongMemEval score for its own memory stack, measured through the same agent surface a production deployment uses, with every confound named in the same breath as the number.

### Problem Statement
arcmemory has no published benchmark (packages/arcmemory/README.md:278,374). Its quality is asserted, not measured. Worse, the two seams that would make a measurement meaningless — the embedder and the distiller — have both silently degraded to no-ops in production before, so an unaudited run would produce a real-looking number for a crippled system. There is also no pathway for bulk-loading an outside corpus into an agent's memory at all, which blocks the email and Slack backfills that come next.

### Value Proposition
One ingest pathway with a pluggable source adapter serves both goals at once: it is how outside corpora reach memory, and it is how memory gets measured. A trustworthy number tells us where arcmemory actually stands against Zep and mem0, turns every future memory change into a measurable delta instead of an opinion, and gives the federal buyer an artifact that is reproducible from a manifest rather than a marketing page.

## Personas

See [.claude/steering/product.md#user-personas](../../steering/product.md#user-personas). Primary here is the **Agent Developer (Internal)** — building and running the harness, tuning arcmemory against the resulting numbers. Secondary is the **Federal/Regulated Security Architect**, who consumes the run manifest as reproducibility evidence and who is the reason dataset, workspaces, traces and credentials must never enter the repo. The **Auditor/Reviewer** persona is not a direct user of this feature.

## User Stories

- **US-1**: As an agent developer, I want one ingest pathway that feeds an outside corpus into a real Arc agent's memory through pluggable source adapters, so that LongMemEval, email and Slack all reach memory by the same route and a new source is one file..
- **US-2**: As an agent developer, I want both LongMemEval metrics recorded per question — QA accuracy from a pinned judge and turn/session retrieval recall, so that a failure splits into 'memory never surfaced it' versus 'memory surfaced it and the answer was still wrong', which are different bugs..
- **US-3**: As a security architect, I want the dataset, the throwaway workspaces, the traces and every credential kept out of the repository and out of plaintext artifacts, so that running a benchmark never becomes the way third-party content and secrets get committed..
- **US-4**: As an agent developer, I want a phased, resumable, spend-bounded run that hard-fails when a measurement seam is unwired, so that an interrupted or degraded run is caught and restarted rather than silently reported as a memory score..

## Functional Requirements

- **REQ-174** (story US-1, Must): The harness SHALL expose one source-adapter contract — a single `read()` yielding sessions of ordered turns, each with a source timestamp and a conversation id — such that adding a new corpus adds exactly one module and requires no edit to the chunker, the agent driver, or the consolidation waiter. (Pillar: Modularity — D-497)
- **REQ-175** (story US-1, Must): The harness SHALL ship the `longmemeval` adapter as the only adapter in this release, reading `longmemeval_oracle.json` and `longmemeval_s_cleaned.json` from a gitignored local data directory. (Pillar: Simplicity — D-497, YAGNI until the seam has a second consumer)
- **REQ-176** (story US-1, Must): WHEN a haystack session transcript exceeds the agent's configured `max_event_chars` THEN the harness SHALL split it into successive chunks on turn boundaries only, at a target of 1700 characters, with a newline separating every turn. (Pillar: Simplicity — D-495; the 300-char margin absorbs NFKC expansion and the date prefix, and the newline confines `_INJECTION_RE` end-of-line deletion to a single turn). Each successive turn will re-input any session date so it is available for retrieval.
- **REQ-177** (story US-1, Must): IF a single haystack turn on its own exceeds `max_event_chars` THEN the harness SHALL mark the affected question `void` with reason `turn_exceeds_cap` and SHALL exclude it from accuracy scoring, rather than allowing `sanitize()` to truncate it silently. (Pillar: Security — `_capture` discards `capture()`'s return value, so truncation is otherwise undetectable through the public path)
- **REQ-178** (story US-1, Must): The harness SHALL prefix every chunk with its session date in the form `[Session date: YYYY-MM-DD]` and SHALL record the pinned session ingest order in the run manifest. (Pillar: Simplicity — D-498; ingest order is what the recency channel actually ranks by, so without the record no two runs are comparable)
- **REQ-179** (story US-1, Must): The harness SHALL ingest each chunk through a real `ArcAgent` turn via `run_collected(...)` after `startup()` has completed, using a distinct session key of the form `ingest:<session_idx>:<chunk_idx>` per chunk. (Pillar: Modularity — D-496; memory scope is `agent_did`-only, so per-chunk keys cost nothing at recall and remove quadratic prompt growth plus compaction)
- **REQ-180** (story US-1, Must): WHEN a chunk is about to be ingested THEN the harness SHALL first run it locally through `arcmemory.security.sanitize` and `privacy_filter` and SHALL compare the output length to the input length. (Pillar: Security — `_INJECTION_RE` deletes its match plus everything to end of line, and ordinary benchmark prose triggers it)
- **REQ-181** (story US-1, Must): IF the sanitize-fidelity check shows a reduction overlapping a turn named by the question's `answer_session_ids` or `has_answer` flags THEN the harness SHALL mark that question `void` with reason `gold_evidence_filtered` and SHALL exclude it from accuracy scoring. (Pillar: Security — a filtered gold turn produces a real-looking low score for a crippled input path)
- **REQ-182** (story US-1, Must): WHEN every chunk of a session has been ingested THEN the harness SHALL await the public `consolidate_poll_once()` directly and SHALL assert that `memory/.consolidate-last-run` advanced and `.consolidate-manifest.json` is absent before continuing. (Pillar: Modularity — D-499; `_CONSOLIDATE_POLL_INTERVAL = 300.0` is a module constant, so per-session cadence is unreachable by config and this is the only reliable quiescence signal)
- **REQ-216** (story US-1, Must): WHEN the harness starts a phase THEN it SHALL assert that the eval agent's consolidation settings match the values this spec depends on — including that `arcagent.modules.memory.capabilities._CONSOLIDATE_POLL_INTERVAL` still equals `300.0` — and SHALL return an error before running if any of them differs. (Pillar: Security — the entire harness-drives-consolidation design in REQ-182 rests on that constant being unreachable by config; if it silently changes, the background loop and the harness's own passes can both fire, and arcmemory has no lock)
- **REQ-183** (story US-1, Must): The eval agent configuration SHALL set `brain = "arcmemory"`, a non-empty `distill_provider`, `consolidate_event_threshold`, `consolidate_idle_seconds`, `consolidate_interval_seconds`, and `[modules.memory.config.dynamics] consolidate_interval_minutes = 0.0` together. (Pillar: Simplicity — D-499; lowering the outer limit while the inner one sits at 60 minutes is a silent no-op, and an empty `distill_provider` makes all the others theatre)
- **REQ-184** (story US-1, Must): The harness SHALL NOT run arcmemory's background consolidation loop and direct `consolidate_poll_once()` calls in the same run. (Pillar: Security — there is no `asyncio.Lock` anywhere in arcmemory, so two passes can interleave on the same SQLite connection and the same manifest file)
- **REQ-185** (story US-1, Should): The eval agent configuration SHALL raise the memory recall envelope to `top_k = 20` and `budget = 8000` tokens. (Pillar: Scalability — at the default `budget = 1024` exactly one 2000-char recall survives `enforce_budget` regardless of `top_k`, so the run would measure the budget rather than the memory)
- **REQ-186** (story US-1, Should): The eval agent configuration SHALL set `[llm.modules.telemetry] store_raw_bodies = false`. (Pillar: Security — the default writes every haystack chunk verbatim as plaintext JSONL inside the repo tree, several GB per full run)
- **REQ-187** (story US-2, Must): WHEN a question's ingest completes THEN the harness SHALL put the benchmark question to the same agent instance and SHALL record the agent's answer verbatim in the result row. (Pillar: Simplicity — D-500)
- **REQ-214** (story US-2, Must): The harness SHALL prefix the question turn with the dataset's question date in the form `[Current date: YYYY-MM-DD]`, taken from the dataset and never from wall-clock time. (Pillar: Simplicity — Arc's system prompt carries no date at all, so without this the agent cannot anchor 'last month'; stamping wall-clock today would anchor it to the run year rather than the haystack's, which fails the same 133 temporal-reasoning questions a different way. Symmetric with REQ-178: session date on the write side, question date on the read side, both harness-side with zero framework change.)
- **REQ-215** (story US-2, Must): IF the dataset provides no per-question date field THEN the harness SHALL derive the current date as the latest date in that question's `haystack_dates`, SHALL record `question_date_source` as either `dataset` or `derived` in every result row, and SHALL fail the preflight if neither source is available. (Pillar: Security — a silently absent question date degrades temporal-reasoning into a memory failure that is not one)
- **REQ-188** (story US-2, Must): The harness SHALL score every answer using a dedicated judge agent that runs through arcagent to arcrun to arcllm, pinned to model id `gpt-4o-2024-08-06`, `temperature = 0`, `max_tokens = 10`, constructed with its own key variable and never sharing a client, config or message list with the system under test. (Pillar: Modularity — CON-3 keeps all LLM calls inside arcllm; the dated string is required because the `gpt-4o` alias silently repoints)
- **REQ-189** (story US-2, Must): The judge agent's prompt templates SHALL be byte-identical to the reference `evaluate_qa.py` prompts, enforced by an automated diff test against a checked-in verbatim copy of those prompts. (Pillar: Security — the reference `print_qa_metrics.py` cannot consume our output, so prompt fidelity is the only remaining basis for comparability to published numbers)
- **REQ-190** (story US-2, Must): WHERE a question id carries the `_abs` suffix the harness SHALL apply the refusal-checking judge prompt, SHALL fold its QA result into its base question type, and SHALL exclude it from retrieval scoring. (Pillar: Simplicity — abstention is a cross-tag on the six types, not a seventh type, and `answer_session_ids` is meaningless for it)
- **REQ-191** (story US-2, Must): WHERE a question's type is `single-session-preference` the harness SHALL pass the dataset `answer` field to the judge as a grading rubric and SHALL NOT string-match against it. (Pillar: Simplicity — the field is a rubric, and fuzzy-matching it misscores roughly 6% of the benchmark)
- **REQ-192** (story US-2, Must): The harness SHALL report task-averaged accuracy as the macro mean over the six question types, overall accuracy as the micro mean over all scored questions, and abstention accuracy separately, and SHALL report retrieval `recall_any@k` and `recall_all@k` at both turn and session level with every k stated explicitly. (Pillar: Simplicity — 'recall' without the any/all qualifier is not comparable to anything)
- **REQ-193** (story US-2, Should): The harness SHALL print a Wilson 95% confidence interval beside every per-type accuracy and SHALL label per-type numbers as directional when the stratum holds fewer than 30 scored questions. (Pillar: Simplicity — at n=13 and 77% observed the interval spans roughly 50% to 92%, which cannot separate two systems)
- **REQ-194** (story US-2, Should): The harness SHALL double-judge a fixed sample of questions and SHALL log the judge agreement rate as a first-class metric, retaining prior labels in the row whenever the judge prompt or model changes. (Pillar: Security — `temperature = 0` does not make the judge deterministic on borderline items)
- **REQ-195** (story US-3, Must): The repository `.gitignore` SHALL exclude the dataset files, all per-question run directories, traces, audit artifacts, generated agent TOML files and the results JSONL, and SHALL additionally guard the repository root against `/workspace/`, `/traces/`, `/.audit/` and `/capabilities/`. (Pillar: Security — D-492; every one of these paths is trackable today, and the root guard catches the `ArcAgent(cfg)`-without-`config_path` leak)
- **REQ-196** (story US-3, Must): WHEN the harness starts a phase THEN it SHALL hard-fail if `git check-ignore -q` does not match the run directory and the results file. (Pillar: Security — D-492 is otherwise enforced by nothing)
- **REQ-197** (story US-3, Must): The harness SHALL read every provider and judge API key from the environment only, and SHALL pass every model-derived artifact field — including exception text — through `arcmemory.privacy_filter` before it reaches the results JSONL. (Pillar: Security — D-492; provider error bodies echo request context)
- **REQ-198** (story US-3, Must): The harness SHALL construct each question's agent with an explicit absolute `config_path`, a unique `[agent] name` of the form `lme-<question_id>`, a workspace-relative `[security] policy_audit_log` and a per-run `ARCSTORE_DATA_DIR`, and SHALL assert that `agent._workspace` resolves under the run directory before any ingest begins. (Pillar: Security — without `config_path` the workspace, traces, audit chain and capability scan root all resolve against the process CWD, which is the repo root)
- **REQ-199** (story US-3, Must): The harness SHALL run the eval agent at `tier = "personal"`, SHALL record the tier in the run manifest and in every result row, and SHALL label every reported accuracy as tier-specific. (Pillar: Security — `MemoryConfig.for_tier` changes the write and decay dynamics, so the number is only meaningful with its tier attached)
- **REQ-200** (story US-3, Must): The run manifest SHALL record that the `workpad` and `policy` modules are enabled and SHALL state that the reported accuracy measures arcmemory together with those two additional LLM summarizers writing into the system prompt. (Pillar: Simplicity — operator decision to keep full production fidelity; the measurement scope must then be declared, not inferred)
- **REQ-201** (story US-3, Must): WHEN a phase starts THEN the harness SHALL verify the dataset SHA-256 against the value recorded in the run manifest and SHALL abort on mismatch. (Pillar: Security — LLM04 data poisoning on a third-party download feeding a memory store; it also makes runs reproducible)
- **REQ-202** (story US-4, Must): The harness SHALL process questions strictly one at a time, with never more than one agent instance live. (Pillar: Simplicity — operator decision; it also removes the shared flocked WORM chain, the shared arcstore and the provider-rate-limit cascade from scope entirely)
- **REQ-203** (story US-4, Must): The harness SHALL run in three gated phases — LongMemEval-Oracle across all 500 questions, then a stratified sample of roughly 50 LongMemEval-S questions covering all six types, then full LongMemEval-S — and SHALL require an explicit flag to enter each later phase. (Pillar: Simplicity — D-500; Oracle first buys a near-free end-to-end proof before ~40,000 ingest calls)
- **REQ-204** (story US-4, Must): The harness SHALL treat the question as the atomic unit of resume, writing a result row only after ingest, query and judge have all completed, with a terminal `"status": "complete"` field, and SHALL treat any question whose row is missing, partial or unparseable as not done. (Pillar: Security — D-500)
- **REQ-205** (story US-4, Must): The harness SHALL write an `.ingest_complete` marker into a question workspace as its final ingest action, and WHEN resuming SHALL delete and rebuild any workspace lacking that marker. (Pillar: Security — chunk-level LLM calls are order-sensitive and not idempotent, so a plausible-looking partial workspace silently produces a worse answer)
- **REQ-206** (story US-4, Must): The harness SHALL append to the results JSONL and never read-modify-write it, building the done-set once at startup and tolerating a truncated final line. (Pillar: Scalability — a truncated final line is the normal SIGKILL signature)
- **REQ-207** (story US-4, Must): WHEN a phase starts THEN the harness SHALL run a live end-to-end preflight in a scratch workspace asserting that the brain is not a `NullBrain`, that `_embedder`, `_distiller` and `_model` are all non-None after startup, that one forced `consolidate_poll_once()` returns True, that `.consolidate-last-run` advanced, that the returned `episode_summary` reports `window_events > 0` and that a `memory/daily-log/*.md` file exists — and SHALL abort the phase on any failure. (Pillar: Security — both seams have degraded silently in production before; `arc agent build --check` tests none of this)
- **REQ-208** (story US-4, Must): The harness SHALL provide a `--dry-run` mode that walks the dataset through the real chunker, sums estimated tokens and multiplies by a versioned pricing table held in config. (Pillar: Scalability — at ~40,000 calls a 20-30% token-count error compounds into a meaningfully wrong ceiling)
- **REQ-209** (story US-4, Must): IF the running spend reaches 110% of the dry-run estimate THEN the harness SHALL abort the run, and the running total SHALL persist so that it survives a resume. (Pillar: Scalability — LLM10 unbounded consumption; a warning is not a control)
- **REQ-210** (story US-4, Must): Every result row SHALL carry `git_sha` with a dirty flag, `harness_version`, `config_hash` over the canonicalized resolved configuration, `dataset_sha256`, `agent_model_id`, `judge_model_id`, `embedder_model_id`, `distiller_model_id`, `tier`, `run_timestamp_utc` and `question_id`, and the harness SHALL additionally write a `run_manifest.json`. (Pillar: Security — a single row must stay self-describing after rows are concatenated across runs)
- **REQ-211** (story US-4, Must): The harness SHALL tear down each question workspace inside a `finally` block, checkpointing SQLite WAL before deletion, and SHALL refuse to start a phase when leftover workspaces from an aborted run exceed a configured threshold. (Pillar: Scalability — deleting the `.db` leaves `-wal` and `-shm` siblings that can exceed the main file)
- **REQ-212** (story US-4, Should): The harness SHALL log `tokens_in`, `tokens_out`, `cost_usd`, `n_llm_calls` and `wall_seconds` per question. (Pillar: Scalability — a median-cost diff against the prior run catches an ingest-cost regression before it burns the full-S budget)
- **REQ-213** (story US-4, Could): WHERE the operator passes `--keep-workspace-on-failure` the harness SHALL retain the workspace of any question that is void, errored or judge-disagreed. (Pillar: Simplicity — cheap post-hoc debugging without paying the disk cost for all 500)

## Success Metrics

Framework: [.claude/steering/product.md#success-metrics-framework](../../steering/product.md#success-metrics-framework) (security/compliance variant, not SaaS).

**Feature-completion metrics** — these gate the feature, not arcmemory's score:

| Metric | Target |
|---|---|
| Oracle phase completes end to end (ingest, consolidate, recall, answer, judge) | 500/500 questions reach a terminal status |
| Questions voided for `gold_evidence_filtered` or `turn_exceeds_cap` | < 2% of the run; every void is attributable to a named turn |
| Preflight catches a deliberately unwired embedder and a deliberately empty `distill_provider` | 2/2 caught, phase aborted |
| Run reproducibility | Two runs at the same `git_sha`, `config_hash` and `dataset_sha256` produce identical void sets and identical retrieval recall |
| Resume correctness | SIGKILL mid-ingest, resume, and finish with the same completed-question set as an uninterrupted run |
| Actual spend against the `--dry-run` estimate | Within 110%; the ceiling aborts rather than warns |
| Repo cleanliness after a full phase | `git status` clean; `git check-ignore -q` matches every run artifact |

**Reported outputs** (the measurement itself, not a pass/fail gate): task-averaged accuracy, overall accuracy, abstention accuracy, and turn-level plus session-level `recall_any@k` / `recall_all@k`. Paper orientation points under a GPT-4o judge: GPT-4o Oracle 0.870, LongMemEval-S full-history 0.606, Zep on S 71.2%.

## Risks and Constraints

| Risk | Mitigation |
|---|---|
| **Measurement-corrupting input filter.** `_INJECTION_RE` deletes its match plus everything to end of line, and `privacy_filter` redacts ordinary prose such as "My secret: I hate cilantro". Gold evidence can be destroyed before it is ever stored, yielding a real-looking low score. | REQ-180/REQ-181: pre-check every chunk locally, void the question when gold evidence shrinks. REQ-176's per-turn newline confines damage to one turn. |
| **Silent seam degradation.** An empty `distill_provider` yields no consolidator; `embed_backend = "none"` drops recall to BM25 plus graph. Neither raises. | REQ-207 live end-to-end preflight, asserted through the real path rather than by self-report. |
| **Comparability loss from the in-house judge.** The reference `print_qa_metrics.py` hard-asserts the judge string and cannot consume our output, so we score with our own script. | REQ-188 pins the dated model id and decoding parameters; REQ-189 enforces byte-identical prompts by diff test; REQ-194 tracks judge disagreement. |
| **Cost blowout.** `Consolidator.run()` uses an unbounded `TimeWindow()`, so every pass re-distills the entire episodic stream — O(n²) in LLM cost over 40 sessions — and the agentic engine breaches `max_tokens = 20_000` by roughly session 3, degrades, and pays for the pipeline anyway. Workpad adds ~2 more calls per question. | REQ-208 real-chunker dry-run, REQ-209 hard aborting ceiling that survives resume, REQ-212 per-question cost telemetry, REQ-203 phase gating. |
| **Temporal confound.** `Event.ts` is `now()`, so recency ranks by ingest order. On Oracle (unsorted) that is actively misleading; on S (timestamp-sorted) it is accidentally correct. All sessions also collapse into one `daily-log/<today>.md` and every `Fact.date` is stamped today, which degrades `knowledge-update` as well as `temporal-reasoning`. | REQ-178 pins and records ingest order; the confound is reported in the same sentence as the temporal number. A free ablation exists via `rebuild_index()`, which NULLs `mtime`. |
| **No date anchor on the read side.** Arc's system prompt carries no date, so 133 temporal-reasoning questions cannot resolve a relative reference like "last month" even on perfect retrieval — a harness gap that would read as a memory failure. | REQ-214 supplies the dataset's question date in the question turn; REQ-215 defines the derived fallback and records which source was used. Note this only anchors the *reader*; the write-path damage above (collapsed daily-log, facts stamped today) is unaffected and remains a reported limitation. |
| **Artifacts and credentials entering the repo.** No `.gitignore` rule mentions `evaluations/` today; `store_raw_bodies` defaults to true; `ArcAgent(cfg)` without `config_path` resolves the workspace against the process CWD. | REQ-195, REQ-196, REQ-197, REQ-198, REQ-186. Note the gitignore gotcha: git cannot re-include a file beneath an ignored directory, so harness code must stay out of `runs/`. |
| **Measurement scope is wider than arcmemory.** `workpad` and `policy` are on, so two further LLM summarizers write into the system prompt each turn. | REQ-200 declares the scope in the manifest. Accepted deliberately to preserve D-496's premise that the agent path is the product. |
| **Dataset defects and version drift.** The Sept-2025 'cleaned' revision is not numerically comparable to the original, and issues #37-#41 and #50 document open gold-label errors. | REQ-201 SHA-256 gate; REQ-210 records the dataset hash in every row; spot-check labels rather than assuming them clean. |
| **Baseline traps.** Published mem0 numbers come from marketing pages with undisclosed reader model and unconfirmed official-judge use. | Report Arc's own numbers with full provenance; do not target a published figure. |

**Constraints:** zero framework changes — every requirement here is satisfied by configuration, by calling public functions, or by harness-side code (D-494/D-496). `evaluations/` stays outside the uv workspace and nothing under `packages/` may import it. CON-3 (all LLM calls through arcllm) holds for the judge as well as the agent.

## Open Questions

- RESOLVED — Arc's system prompt carries no date at all (`assemble_system_prompt` builds from `identity.md`, `context.md` and module-injected sections only; verified no date in the prompt path, the arcrun strategies or the memory module). Closed by REQ-214/REQ-215: the harness supplies the dataset's question date in the question turn. Still to confirm against the real file: whether the dataset ships a per-question date field or the derived fallback applies.
- Can arcllm's SPEC-038 budget or circuit breaker trip mid-run and turn distillation into a silent no-op? Not traced. A long full-S run is exactly the workload that would trip it, and it would degrade the measurement without raising.
- Should the sampled-S stratification weight the six question types evenly or match the full set's natural distribution? Proportional sampling puts `single-session-preference` at n=3. Deferred until Oracle results show which types are weakest.
- Should `consolidate_engine = "pipeline"` be set for the eval to avoid paying for a doomed 20k-token agentic attempt before every pipeline pass? It is a cost saving that changes what is measured, so it needs an explicit recorded call.

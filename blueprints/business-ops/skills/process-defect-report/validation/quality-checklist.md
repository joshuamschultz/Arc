# Quality checklist — process-defect-report

- [ ] The repeat threshold applied is stated, with the counts.
- [ ] The individual slip instances are listed with dates, commitment, and step.
- [ ] The step where work stalls is named precisely (usually a handoff).
- [ ] The defect is stated as a property of the process — no person is named in it.
- [ ] Process problem and capacity problem are distinguished, and which one this is, is stated.
- [ ] Exactly one change is proposed.
- [ ] The change is structural — not "add a checklist" or "communicate better".
- [ ] What we should observe if it worked is stated, with a date.
- [ ] A corrected process definition was written back with `ops_log_process` where applicable.

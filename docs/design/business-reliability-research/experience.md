# Arc experience and business reliability research

> Initial findings are a research snapshot against local `1850fd3a`. Later patch evidence may be appended. See [the implementation record](../business-reliability-program.md#implementation-record) for current fixes and final verification.

Static inspection only; no runtime reproduction, tests, or profiling were run. File:line references are repository paths under `/Users/joshschultz/Projects/arc`. Severity estimates are for the operator's daily product experience. Existing specs are noted to avoid rebuilding shipped work.

## Highest-confidence findings

1. **P0, image uploads never become vision input.** Owner: ArcUI upload route, with ArcGateway/ArcAgent contract tests. `packages/arcui/src/arcui/routes/attachments.py:69-78` always passes `kind="file"` to MediaStore, including an image. MediaStore detects and records the actual MIME but persists the supplied kind (`packages/arcgateway/src/arcgateway/media_store.py:309-348`). Gateway forwards that kind unchanged (`packages/arcgateway/src/arcgateway/bootstrap.py:244-269`). `packages/arcagent/src/arcagent/parts.py:132-156` creates an `arcrun.ImageBlock` only for `kind == "image"`; generic files become a text reference. This statically proves the reported browser-image path cannot reach a vision model as pixels. Existing `packages/arcui/tests/integration/test_attachment_session_identity.py:81` expects `kind="file"` for PNG, so it codifies the wrong contract. Fix: derive canonical media kind after MIME detection, preserving custody/signature/session checks, and assert PNG upload → clean claim → `MediaPart(kind=image)` → `ImageBlock` in an end-to-end test. Add image MIME spoofing, unsupported format, and agent/session mismatch refusals to the adversarial battery. A model/provider with no vision capability should return a clear unsupported result, not imply it saw the image. Runtime behavior beyond the deterministic kind path is unverified.

2. **P1, a long-open Tasks board has a frozen seven-day window.** Owner: ArcUI web. `packages/arcui/web/src/components/task-board.tsx:55-74` captures `Date.now()` once at component mount and uses it forever as the 7-day cutoff. Polling tasks every four seconds (`web/src/lib/queries.ts:121-136`) cannot advance that cutoff. After days idle, done/failed cards stay visible beyond the selected window and counts disagree with a newly opened board. Fix a time-derived view with a low-frequency timer or derive cutoff from a query clock that updates on resume; avoid rerendering every second. Deterministic acceptance: fake the clock, mount the board, advance eight days, trigger visibility resume, verify an old done task exits the 7-day view but an active task stays visible; scope `all` retains all records. Existing scope logic needs this specific idle test.

3. **P1, large task histories create repeated full-payload work.** Owner: ArcUI/ArcStore Observe seam. `packages/arcui/src/arcui/routes/team_pages.py:199-222` returns every task when the board omits `window`; `web/src/lib/queries.ts:127-136` repeats that full request every four seconds. `web/src/pages/tasks.tsx:35-124` rescans the full set for filters/metrics, while `web/src/components/task-board.tsx:69-85,126` filters, sorts, then maps all visible cards. This is a static scaling mechanism, not proof it currently exceeds a latency budget. Fix with server-side pagination/window plus aggregate counters or bounded incremental polling and list virtualization, keeping dependency status available for blocked-task display. Profile 100/1,000/10,000-task fixtures: API response bytes, SQL time, React commit duration, FPS and memory; compare an idle board for one hour. Preserve task mutation/selection across pages.

4. **P1, nonpolled screens can stay stale after long idle.** Owner: ArcUI web. Global query config disables `refetchOnWindowFocus` (`packages/arcui/web/src/App.tsx:9-12`); most shared queries use no interval (`web/src/lib/queries.ts:103-119,1490-1505`). A tab left on Connections or Tools/Skills can continue to show previous data after a backend restart or another operator's change until navigation/remount or explicit invalidation. This is an inference from query semantics, not a witnessed failure. TanStack documents focus revalidation and reconnect behavior: https://tanstack.com/query/latest/docs/framework/react/guides/window-focus-refetching and https://tanstack.com/query/latest/docs/framework/react/guides/important-defaults . Fix by restoring focus revalidation for operational data or using a bounded explicit resume refresh, while preserving unsaved form state. Test hidden → backend data changes → visible and offline → online for roster, connections, skill inventory, knowledge status.

5. **P1, default skill self-improvement is intentionally inactive and lacks a clear setup/status journey.** Owners: ArcAgent skills configuration and ArcUI. `packages/arcagent/src/arcagent/modules/skills/config.py:21-43` sets `adapter="none"` and `classify_outcomes=False`, so an untuned install will not improve skills even though `arcskill.improver` exists. This is expected optionality per `packages/arcskill/AGENTS.md` and `.claude/specs/SPEC-044-skill-improver/SDD.md`, not evidence of a broken trigger. The UI does show versions/diffs/rollback (`packages/arcui/web/src/components/skill-drawer.tsx:107-173,282-300`), but no explicit adapter activation/status/blocked-reason journey was found in the scanned ArcUI routes/pages. For a $20/month push-button product, add a bounded operator setting and status that reports `off / waiting for eligible signal / evaluating / blocked with reason / promoted`, costs and safety limits; keep the default safe and do not globally turn on expensive improvement. Acceptance: fresh install can enable a defined low-cost policy in ArcUI, exercise a seeded failing skill, see evidence-gated promotion or a truthful no-change reason, restart, and see persisted configuration/status. Check `.claude/specs/SPEC-054-skill-improver-eval-bootstrap/SDD.md` first; its classifier and sweep design already exists.

6. **P1, imported/global skills are read-only in the primary skill drawer, while workspace editing can invalidate trust.** Owners: ArcUI and ArcAgent capability mutation seam. `packages/arcui/src/arcui/routes/agent_detail/skills.py:24-27,61-80` marks only agent/workspace roots editable. The drawer hides Edit when `editable=false` (`web/src/components/skill-drawer.tsx:113-133`) and writes editable content through generic file PUT (`:70-82`). That route documents that modifying a signed file leaves its signature stale (`routes/agent_detail/files_write.py:39-45`), and the drawer only displays a warning (`skill-drawer.tsx:142-150`). This behavior is deliberate fail-closed for builtins and signed imports, but from the user perspective there is no end-to-end edit/review/resign/activate path for a promoted skill. `packages/arcui/web/src/components/capability-import-panel.tsx:172-241` already supports ZIP upload, staged file edit and promote/sign; `.claude/specs/SPEC-081-open-skill-packages/PRD.md` and PLAN already describe rich skill package import, and existing import security tests cover path/binary/no-execute checks. Extend or link the existing review pathway for edits/forked revisions, with actor authorization, reapproval and rollback; never make installed signed artifacts directly writable. Acceptance: upload a skill-creator ZIP with nested folders, review/edit, promote, use, edit as a new revision, sign/reapprove, see it loaded after restart; malicious path/symlink and unsigned tampering remain refused.

7. **P1 hypothesis, Knowledge enrollment can render a disabled dead end.** Owner: ArcUI connection card plus connected-source service. The card shows a Knowledge action per grantee (`packages/arcui/web/src/pages/connections.tsx:216-239`), but `ConnectionKnowledgeAction` disables it when the module is present yet no matching source appears (`:373-424`, `(!unavailable && !enrolled)`). In that state the UI says `not indexable`, even though `knowledge_mode` may not be `non_indexable`; it offers no discovery/retry/diagnostic action. The route returns `status=degraded` only when the service is absent (`packages/arcui/src/arcui/routes/connected_data.py:152-157`), so an active service returning zero items creates this state. Need distinguish unsupported, not discovered, provider error, auth expired and truly non-indexable from the canonical adapter status, and give an actionable retry/enroll path. Acceptance: a granted connection with an active module but empty `list_sources()` shows a specific reason and recovery control; provider recovery yields a discovered source, resource select/mapping approval/sync, then a retrieval with provenance. Add restart/credential-expiry/provider-timeout tests. The user's particular account state is unverified.

8. **P2, screen help and safe HTML report viewing are product gaps.** Owner: ArcUI. `packages/arcui/web/src/app/router.tsx:23-64` has no help or report route; `web/src/components/page-header.tsx:3-27` offers no help affordance, while page-local descriptions are brief. A search of source UI found no HTML report viewer/iframe; the only `/help` is a chat command (`web/src/pages/messages.tsx:663-667`). Build contextual help for each main screen, with a first-action, expected state, and recovery path for 403/503/provider/config errors. For HTML reports, show a provenance/header outside an isolated document viewer. Use a sandboxed iframe without `allow-same-origin` or `allow-scripts` by default, strict CSP (`default-src 'none'`, scoped images/styles only as required), no app token access, bounded bytes and dimensions, no arbitrary network fetch; provide a separate explicit export/download action. MDN warns that same-origin + scripts can nullify iframe sandboxing: https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe ; OWASP recommends sandboxing untrusted content: https://cheatsheetseries.owasp.org/cheatsheets/HTML5_Security_Cheat_Sheet.html . Acceptance: trusted report renders, embedded script/form/external fetch/parent-navigation attempts fail; content provenance and open/download actions are audited and scoped. This is design guidance, not a present exploit claim.

## Tasks and group chat: findings and repro plan

The controls and routes exist: task create sheet (`web/src/components/create-task-sheet.tsx:49-69`), `POST /api/team/tasks` (`routes/tasks.py:95-133`), new-channel sheet (`web/src/components/channel-management.tsx:69-137`), `POST /api/team/channels` (`routes/team_chat.py:184-251`). Both are operator-only, and UI gates them behind manually enabled operator mode (`web/src/pages/tasks.tsx:140-150`, `web/src/pages/messages.tsx:743-749`, `web/src/hooks/use-operator-mode.ts:3-37`). This can explain “cannot create” when the switch is off or a viewer token is used, but no static defect proves the reported failure. The channel form requires comma-separated raw refs (`channel-management.tsx:121-130`), while the route resolves each via the registry and returns 400 for unknown refs (`team_chat.py:215-230`); use an agent picker with exact DID refs rather than asking customers to guess handles. The operator-mode state is localStorage-only and independent of actual server role (`use-operator-mode.ts:3-9`), so an operator can see hidden controls until enabling a second switch, and a viewer can turn them on only to get 403. Reproduce with a real operator token and viewer token after clean install and restart, submit a task/channel with one valid roster agent, inspect request/response/audit and UI error; repeat after messaging service/broker interruption and restoration. Existing route tests: `packages/arcui/tests/test_task_mutation_routes.py`, `packages/arcui/tests/test_team_chat_routes.py` (verify path if renamed). Avoid claiming a backend create bug without this run.

Recommended reliability acceptance matrix for the product: first install with zero manual shell setup; 24-hour and 7-day idle tab/server restart; provider credential expiration and reconnect; offline/online; broker outage; invalid signature/revocation; 10k-task board; image upload under vision and text-only models; rich skill ZIP import/edit/reapprove; knowledge grant → source discover → mapping approval → sync → retrieval. Every error state must name the failed seam, last good status, recoverable action, and correlation/audit ID without exposing secrets. Verify all mutations retain operator authorization and audit; run architecture and adversarial batteries for security-sensitive changes.

## Image fix and verification (2026-09-23)

The image upload defect is fixed on local main. `arcgateway.parts.kind_for` is the sole MIME-to-kind classifier; `MediaStore.store_stream` derives manifest kind from its detected, declaration-validated MIME. ArcUI no longer supplies a hardcoded `file` kind, and Slack, Mattermost and Telegram import the same lower-level classifier directly. The browser upload → claim → session-history → `PartTranslator` test proves a PNG reaches `arcrun.ImageBlock`; a PDF remains a file, and a PDF falsely declared PNG is rejected without a manifest. The legacy caller-supplied `store_stream(kind=...)` contract and duplicate classifier were removed.

Test-first RED: browser journey and media custody tests failed `file != image` before implementation. GREEN: focused 38 tests passed; strict mypy passed in 156 ArcGateway/ArcUI source files; Ruff check and format passed on 14 touched implementation/test files; `git diff --check` passed. Required adversarial battery passed 413 tests, 0 skipped, 5 deprecation warnings after fixing its ArcUI approvals fixture to set both `ARC_CONFIG_DIR` and `ARC_TEAM_ROOT` to the same tmp root. Under battery isolation, `ARC_TEAM_ROOT` otherwise overrode the fixture's config path and the route could not find its generated operator key; isolated-home test reproduced the 500 before and passed after. Broad ArcGateway/ArcUI suites passed 2427 tests, 6 skipped, 3 deprecation warnings using the declared optional Mattermost `aiohttp` dependency. That run also found a stale fixed-date pending-question fixture that failed on 2026-09-23; changing its timestamp to current UTC preserved the production expiry behavior and made the affected 10-test file and full package suites pass. No production behavior outside media classification was changed.
